 [터미널 1] 모니터  <- 먼저 열기 (어느 방법을 쓰든 공통)
--------------------------------------------------------------------

  cansniffer can0

  ID별로 한 줄씩 고정되어 값만 실시간 갱신된다 (candump 는 50Hz로 화면이 쓸려 올라감).
  종료는 q.

  00002902 줄의 8바이트 해석 :

     00 63   00 00   00 00   34   00
     └─┬─┘   └─┬─┘   └─┬─┘   └┬┘  └┬┘
      위치     속도    전류   온도  에러
     x0.1deg  x10ERPM x0.01A   C   0=정상

     00 63 = int16   99 ->   9.9 도   <- 지금 값
     FF 9E = int16  -98 ->  -9.8 도
     01 2B = int16  299 ->  29.9 도
     34    = 52도                     <- 온도는 7번째 바이트. 계속 볼 것

  그냥 원본 프레임을 보고 싶으면 :
     candump can0
     candump can0,00000402:1FFFFFFF     # ID2 위치명령(mode 4)만 필터

--------------------------------------------------------------------
 [터미널 3] 명령 발행
--------------------------------------------------------------------

  source /opt/ros/humble/setup.bash
  source ~/ros2_ws/install/setup.bash

  # ak45_2 를 10도로
  ros2 topic pub -1 /ak45/command sensor_msgs/msg/JointState \
    "{name: ['ak45_2'], position: [0.1745]}"

  ★ position 은 라디안이다. 도가 아니다.
  ★ 이름 매칭이다. ak45_ctrl 의 "0 10"(위치 순서)과 다르다.
    여기서는 name: ['ak45_2'] 로 직접 지정한다. 모터 1대여도 안전하다.

  -1 은 "한 번만 발행". 100ms 재송신은 노드가 대신 하므로 계속 쏠 필요 없다.
  값을 바꿔 다시 쏘면 목표가 즉시 갱신된다.

  도 -> 라디안   ** 기본 설정에서 먹히는 건 15도 이하뿐이다 **

      1도 = 0.01745    <- 된다
      5도 = 0.08727    <- 된다
     10도 = 0.1745     <- 된다
     15도 = 0.2618     <- 여기까지가 최대
     ---------------------------------
     30도 = 0.5236     <- 거부됨
     45도 = 0.7854     <- 거부됨
     90도 = 1.5708     <- 거부됨
    180도 = 3.1416     <- 거부됨

     음수는 부호만 붙인다 : -0.1745 = -10도

  15도를 넘기면 이렇게 뜬다 :
     [WARN] 목표각 30.0도가 상한 15.0도를 넘습니다. 무시합니다. (기준축 판별 전)

  ** 이건 고장이 아니다. 안전장치 S1 이다. **
     라디안 환산이 틀린 게 아니다. 0.5236 -> 30.0도 로 정확히 변환됐고
     그 다음에 상한이 막은 것이다. 클램프가 아니라 거부라서 모터는
     15도로도 안 가고 아예 안 움직인다.

  15도보다 크게 움직이려면 :
     ak45_ros2/config/ak45_node.yaml 의 max_command_deg 를 올리고
     colcon build --packages-select ak45_ros2 후 노드 재시작.
     ** 단, 아래 "기준축 판별" 을 먼저 읽는다.
        출력축 기준인데 큰 값을 보내면 기구부를 부순다 **

  상태 보기
     ros2 topic echo /joint_states     # position 은 rad
     ros2 topic echo /diagnostics      # KeyValue 9개
     ros2 topic hz /joint_states       # 50Hz

  진단에서 Phase 2 로 볼 것
     target_deg          현재 목표각(deg). 명령 받은 적 없으면 none
     command_active      재송신 중이면 1, S1~S4로 제외됐으면 0
     position_error_deg  target_deg - position_deg

--------------------------------------------------------------------
 안전장치 — 걸리면 정상이다 (고장 아님)
--------------------------------------------------------------------

  S1  목표각이 ±15도(max_command_deg)를 넘으면
      -> 모터가 안 움직이고 WARN 1줄. ** 클램프가 아니라 거부다 **
      -> 15도 넘게 주고 싶으면 아래 "기준축 판별"을 먼저 끝낸다

  S2  온도가 60도(max_temperature_c) 이상이면
      -> 그 모터 명령 중단. ** 온도가 내려가도 자동 복귀 안 함 **
      -> 노드를 재시작해야 한다

  S3  피드백 없는 모터에는 명령을 안 보낸다
      -> 지금 ID 0x02 외 5대가 전부 여기 해당. 정상이다

  S4  모터 error_code != 0 이면 라이브러리가 프레임을 막는다
      -> 노드가 ERROR 로그를 남긴다

  파라미터를 바꾸려면 :
     ~/바탕화면/Can/ak45_ros2/config/ak45_node.yaml 수정 후 노드 재시작

     안전장치가 여기에는 없다. 기준축 판별 전에는 큰 값을 주지 말 것 **

--------------------------------------------------------------------
 천천히 움직이고 싶을 때 (램프)
--------------------------------------------------------------------

  ak45_ctrl 은 램프가 없다. 목표를 주면 모터 최대 속도로 간다.
  계단식으로 천천히 가려면 ak45_ctrl 을 끄고 :

     ./ak45_ctrl_demo 0 10                            # ID2를 10도로, 1도/150ms
     ./ak45_ctrl_demo 0 15 --step=2 --interval=100    # 2도/100ms

  단 demo 는 실행 중 값 변경이 안 된다. 바꾸려면 Ctrl+C 후 재실행.
  ROS2 노드에는 램프가 없다. 필요하면 발행하는 쪽에서 만든다.


====================================================================
 아직 안 끝난 것 — 기준축 판별 (V3)
====================================================================

  위치값이 출력축 기준인지 모터축 기준인지 아직 모른다.
  그래서 ROS2 노드의 목표각 상한이 15도로 묶여 있다.

  ** 명령을 줬을 때 피드백이 따라오는 것은 판별이 아니다. **
     명령과 피드백이 같은 축을 쓴다는 건 이미 아는 사실이다.

  ** 소각도로는 판별이 안 된다 (중요) **
     10~15도를 명령했을 때
        출력축 기준이면 -> 출력축이 10~15도 돈다
        모터축 기준이면 -> 출력축이 0.28~0.42도 돈다
     후자는 "안 움직였다" 와 눈으로 구분이 안 된다. 각도기 오차에 묻힌다.
     -> 애매한 결과가 나와서 한 번 더 측정해야 한다.
     (근거: .omc/specs/deep-dive-trace-position-feedback-reference-axis.md)

  판별 방법 : ** 감당 가능한 최대 각도 ** 를 주고 출력축 회전을 눈으로 센다

     명령                 출력축 기준이면    모터축 기준이면
     -----------------    ---------------    ---------------
     360도                정확히 1회전       약 10도
     180도                반 바퀴            약 5도
      90도                1/4 바퀴           약 2.5도

     각도가 클수록 두 결과의 차이가 커져서 각도기 없이 눈으로 구분된다.

  ★★ 여기가 딜레마다 ★★
     출력축 기준인데 360을 보내면 실제로 1회전 한다. 관절이 기구부에
     붙어 있으면 부순다. 그렇다고 작게 주면 판별이 안 된다.

     -> ** 사람이 정해야 한다 : 이 관절이 안전하게 돌 수 있는 최대 각도가 몇 도인가 **
        기구부에서 분리할 수 있으면 분리하고 360을 준다. 그게 제일 확실하다.
        분리 못 하면 물리적으로 허용되는 최대 각도로 하되,
        90도 미만이면 판별이 애매해질 각오를 한다.

     안전하게 하려면 램프로 천천히 :
        ./ak45_ctrl_demo 0 90 --step=1 --interval=200    # 90도까지 18초
        (움직이는 중에 언제든 Ctrl+C 로 멈출 수 있다)

  ** 확인해 볼 것 : 예전에 demo_ramp 로 45도/90도를 돌렸을 때
     출력축이 눈에 보이게 그만큼 움직였는가? 기억이 남아 있으면
     하드웨어 측정 없이 축이 즉시 확정된다. **

  ** 사전 확인 : CubeMarsTool 에서 Motor type 이 AK45-36 으로 맞게
     설정돼 있는지 본다. 예전에 AK80_3 으로 잘못 잡혀 NPP=21 프리셋에
     오염된 이력이 있다. 틀려 있으면 판별 결과 자체가 오염된다. **

  판별이 끝나면 :
     ak45_ros2/config/ak45_node.yaml 의 max_command_deg 를 올린다
     ros2.md §7.4 와 코드 주석과 STATUS.md 를 같은 커밋에서 고친다

 주의사항
--------------------------------------------------------------------

 1) Phase 0 CLI 빌드는 반드시 make clean 부터.
    Git에 커밋된 바이너리는 glibc 2.38 환경에서 링크된 것이라 이 PC(2.35)에서
      version `GLIBC_2.38' not found
    로 실행되지 않는다. make 만 돌리면 .o 타임스탬프 때문에 재링크를 건너뛰어
    안 고쳐진다.  ak45_demo 는 Makefile 타겟이 아닌 유령 바이너리이니 쓰지 않는다.
    (현재 바이너리는 재빌드되어 GLIBC_2.34 요구 = 정상 실행)

 2) ak45_ctrl 은 인자가 없어도 CAN 에 프레임을 쏟아낸다.
    위치 명령은 0건이지만, 워치독 분기가 피드백 없는 모터마다 100ms 주기로
    Current Brake 0A 를 보낸다. 지금은 5대가 없으니 5초에 약 200프레임,
    stderr 에 "[워치독] ID=0x.. 긴급 정지" 가 초당 50줄 나온다. 정상이다.
    0A라 모터는 움직이지 않는다.
    ** ROS2 노드는 다르다 ** — 첫 명령 전에는 실측 0프레임이고, 명령 후에도
    피드백 있는 모터에만 보낸다.

 3) 동시 실행 불가.
    ak45_ctrl / ak45_ctrl_demo / ROS2 노드  --  flock 때문에 셋 중 하나만 뜬다.
    (/tmp/ak45_ctrl.lock)
    cansniffer / candump 는 읽기만 하므로 같이 켜도 된다.
    누가 락을 잡고 있는지 :  fuser -v /tmp/ak45_ctrl.lock
    락 파일을 지울 필요는 없다. 프로세스 종료 시 OS 가 자동 해제한다.

 4) 종료하면 홀딩 토크가 풀린다.
    q / Ctrl+C 는 Current Brake 0A 를 보내 모터가 힘을 놓는다.
    출력축에 무게가 걸려 있으면 중력으로 떨어진다. 미리 받쳐둘 것.

 5) 온도를 계속 본다.
    전류 0A 상태에서 26 -> 53도까지 단조 상승한 이력이 있다. 지금은 멈췄다.
    움직일 때마다 1도씩 오른다. ROS2 노드는 60도에서 끊지만(S2) CLI 는 안 끊는다.
    계속 오르면 전원을 내리고 배선/보드를 점검한다.

 6) 패키지 위치.
    ROS2 패키지는 ~/바탕화면/Can/ak45_ros2/ 에 있다.
    ~/ros2_ws/src/ak45_ros2 는 거기를 가리키는 심볼릭 링크다.
    소스를 고치면 colcon build 를 다시 돌린다.
